Stage 1 · The maths

Tasks 1–6

A standalone calculation library with no Angular code, so it can later move to a TradeSmart server unchanged.

Task 1

Project setup

New Angular 22 workspace with Ionic, Vitest and Playwright.

Test: a smoke test runs
Task 2

Option pricing and Greeks

Black-76 prices, delta, gamma, theta, vega, ITM probability.

Test: matches textbook values to 8 decimals
Task 3

Implied volatility

Solves IV from each option's price. Picks bid/ask mid or last price. Never invents a number.

Test: 14 known IVs, plus "–" cases like price below intrinsic
Task 4

Expiry time and forward price

Days-to-expiry label ("5d"), time to 15:30 IST, forward price from call and put prices.

Test: 29 Oct 10:00 → 3 Nov shows "5d"
Task 5

Chain totals

Max Pain, PCR, OI change and OI Sense, straddle and decay, GEX.

Test: sample chain gives Max Pain 25000, PCR 1.04
Task 6

Whole-chain calculation

Runs everything for all strikes in one call.

Test: 150 strikes in under 50 ms, no errors on expiry day

Stage 2 · Live data

Tasks 7–9

Connecting to Kambala, keeping prices current, and running the maths in the background.

Task 7

Kambala connection

REST calls, the live WebSocket feed with automatic reconnect, and a mock feed for demos.

Test: a price-only update never wipes OI or bid/ask
Task 8

Expiries, contracts and live store

Loads expiries and strikes, reads lot size per contract, subscribes to the whole chain.

Test: fast expiry switching never shows the wrong strikes; SENSEX Jan-27 lot is 25
Task 9

Background calculation

Recalculates once a second in a worker, skips if busy, recovers from a crash.

Test: no pile-up of slow calculations

Extra checks built into the plan

Situations the spec doesn't spell out but traders will hit. Each has its own test.

Partial price updatesAn update with only the price must not reset OI or bid/ask.
Illiquid strikesNo quote means IV shows "–", but OI still counts in PCR and Max Pain.
Fast expiry switchingNever shows one expiry's strikes under another's label.
Expiry day after 15:30Shows "expired", never huge or broken Greeks.
Spot sitting on a strikeThe spot line stays put instead of flickering.

How should I build it?

Recommended

Task-by-task with a reviewer

A fresh agent builds each task, and a separate reviewer checks it before the next one starts, then a final review of everything. Slower and uses more tokens, but each task is checked independently. That matters here because later tasks rely on the exact names and numbers from earlier ones.

All in this session

I build every task myself, then one reviewer checks the whole result at the end. Faster and cheaper, but mistakes are only caught at the end.
