    How it works

    From Kambala to the screen

    The chain subscribes to every strike of the selected expiry, so Max Pain, PCR and GEX are always correct. The strike count only changes how many rows you see.

    Find expiriesGetLinkedScrips returns each expiry and a sample symbol
    Load contractsGetOptionChain returns call and put tokens for every strike
    SubscribeWebSocket touchline for all contracts, the index and the future
    Merge ticksPartial updates merged per contract, about 4 screen updates a second
    CalculateA background worker computes IV, Greeks, Max Pain, PCR and GEX once a second
    RenderOnly rows that changed redraw. The view preset decides the columns.

    Why calculate IV ourselves

    No Kambala endpoint returns implied volatility. GetOptionGreek takes volatility as an input. We solve IV from each option's price with a standard, tested method.

    Why a custom table

    The strike column sits in the middle and a spot-price row moves through the table. Grid libraries like AG Grid can't do either without workarounds. The table is small (about 6,000 cells), so plain HTML is fast enough.

    Portable maths

    The calculation library is plain TypeScript with no Angular code. It can move to a TradeSmart server later without changes.

    Agreed decisions

    What the numbers mean

    ValueHow it is calculated
    IVBlack-76 model on each expiry's own forward price, derived from call and put prices. Uses the bid/ask mid when the spread is tight, otherwise the last price. Shows "–" when it can't be solved.
    Delta · Gamma · Theta · VegaAgainst spot. Theta is ₹ per calendar day. Vega is ₹ per 1 volatility point.
    ATM / ATM IVThe strike nearest the forward price. ATM IV is the average of call and put IV at that strike.
    OI Change · OI SenseOI minus previous-day OI. The sense label combines price direction with OI direction: Long Build Up, Short Build Up, Short Covering, Long Unwinding.
    Max Pain · PCR · Cum OI · GEXAlways from every strike of the expiry, whatever the strike count
    ITM probabilityRisk-neutral N(d2)
    Days to expiryCalendar days to 15:30 IST on expiry day
    Interest rate5.75%, configurable
    When things go wrong

    Error handling

    Connection

    • Connection drops: reconnect at 1, 2, 4… up to 30 seconds and resubscribe. Last prices stay, dimmed.
    • Session expires: hand off to TradeSmart's existing login. No retry loop.
    • Too many subscriptions: show strikes around ATM and a "Partial chain" badge.

    Data

    • No price: "–". OI still counts in totals.
    • IV can't be solved: "–", with the reason on hover.
    • Last hour before expiry: IV marked low-confidence.
    • Expiry switched fast: late responses are discarded.

    App

    • Calculation worker crashes: restart once, then show prices only.
    • Market closed: show last data "as of 15:30", no flashing.
    • Saved settings unreadable: fall back to defaults.
    Before build starts

    Open questions

    For Kambala

    • Maximum strikes per GetOptionChain call, and the subscription limit per session
    • Is OI reported in lots or in quantity?
    • SENSEX and BANKEX (BFO) option chains: not in the API document
    • Production URLs, rate limits, heartbeat interval
    • How many WebSocket connections one login may hold, since each chain tab opens its own
    • Does GetQuotes return OI for F&O?

    For the TradeSmart tech team

    • Angular and Ionic versions in production
    • Existing state library and Kambala socket service to reuse
    • Order window and basket service interfaces
    • How today's SENSEX chain finds BFO contracts
    • Can a new tab reuse the login session without signing in again?

    Product (defaults chosen)

    • Mid price or last price for IV (default: mid)
    • Interest rate default and owner (5.75%)
    • ATM from forward (default) or spot
    • Str Decay: change vs previous close (default)
